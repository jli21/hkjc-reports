How each evaluation year was fitted

The 2016 evaluation model was trained on the initial 2010-2015 set. Each later evaluation adds the preceding complete season, so the training window expands by one year; the 2026 model uses 2010-2025. Every evaluation year is fitted separately -- 11 fits in all -- and no evaluation year's outcomes appear in its own fit.

Deltas in this report use model_minus_market_log_loss: race_multinomial_log_loss, where negative is better. That is stated because three delta fields existed in this repository and they did not all point the same way.

Provenance -- the source commit, the config and data digests, the environment and every input this report read by content digest -- is in the technical appendix and in run_lock.json beside this file. Canonical publication fails without it.

Evaluation population and market reference

The market reference

Every metric below is reported beside the market's own implied probabilities on the same races, normalised within each race, and the delta is this model's race log loss minus the market's on the same races. One yardstick across every published report, so their headline numbers mean the same thing and can be read against one another. The market is a measurement, not a model this one is defined against.

The evaluation population

Every figure in this report covers the standardized evaluation window, which begins in 2016. One window for every published report, so their headline numbers are computed on the identical race keys and can be compared -- which is checked by digest before anything is published, not asserted in a footnote. 2015 is earlier than the window and is excluded from every evaluation figure below, including the bankroll paths. The feature-effect grid is the one exception, and says so where it appears: a learned response direction is a property of each year's fit rather than of the evaluation population.

Ensemble stability

Not applicable to this model. There is no ensemble to be stable: this run fitted a single seed, so there is no member disagreement to measure. The headline probability is that one fit's own output, which the identity card states.

Feature and correction effects

Not applicable to this model. There is no market correction belonging to this model to attribute. This model learns a utility directly from the feature matrix, in which the market's implied probability is one ordinary column rather than a base margin, so a per-feature attribution here would decompose the utility -- a different quantity from the market correction the attribution artifact declares, and not comparable with the effects reported for the market-anchored models. What this model's features do to its probabilities is therefore not published rather than published under a name that would mislead.

Betting and bankroll analysis

Not applicable to this model. No bet ledger has been settled for this model. It is the unanchored baseline the offset architecture exists to improve on, and it has not passed a promotion gate; settling it would produce a bankroll path that reads as a recommendation for a model nobody proposes to stake.

Not applicable to this model. There is no settled outcome to put an interval on. Limitations and the retrospective-odds warning

Retrospective odds, restated

Every stake, return and bankroll figure in this report is computed against historical result-page odds and official dividends. Those are not an executable pre-race price: they are the prices after the pool closed, and a bet placed at them could not have been placed. Nothing here establishes profitability. A profitability claim requires a locked model shadow-tested against timestamped pre-race odds snapshots.

This report publishes no stake, return or bankroll figure -- see the betting section for why -- so nothing here rests on that warning. It is restated anyway, because the odds it concerns are the same historical result-page odds every settlement in this repository uses, and a reader arriving here should not conclude the limitation has been lifted.

Every test year is also development data

Every year through 2026 has been used as development data in this repository: features were searched, architectures compared and thresholds inspected against these same seasons. The chronological split is real, so a test year is genuinely after its training rows, but no test year is unseen. Treat the forward figures as probability progress rather than as a locked out-of-sample result, and do not select a Kelly level or an edge threshold from this reused history. The confirmation step that this run cannot substitute for is a prospective shadow test against archived pre-race price snapshots.

What else this report does not establish

  • It measures Softmax against the market on the same races. It does not measure this model against the other published models except through that shared yardstick.
  • It publishes no interval, so no figure in it carries a stated sampling range at all -- a single number is not evidence of precision.
  • Every figure is out of sample in time but in sample in design: the feature set, the hyperparameters were chosen with these years visible.
  • Nothing here is a shadow test. A profitability claim needs a locked model run forward against timestamped pre-race prices.
